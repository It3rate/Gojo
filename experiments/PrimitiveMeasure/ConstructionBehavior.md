# Let the retained structure respond

## What this experiment is trying to show

A generating machine can disappear while leaving useful traces in its output:
an ordered walk, aligned uses, shared reaches or an oppositely used seam. Those
traces can suggest a useful default without proving a unique construction
history. This experiment loads the retained encoding independently, connects a
small explicit behavior to it, and tests what a single request can do.

The intended connected shapes are:

```text
retained family + directed uses
  -> local site correspondence
  -> [source activation, guard, target activation] passages
  -> predicted alternatives -> committed transition -> retained trace

retained value field -> adjustment dial -> [resting, farther] landmarks
input reserve -> waiting request -> adjustment dial
                         ^
                     local pin
```

These are two selected behaviors over the same retained form. A direction arrow
is not automatically a material law: the passage connections make that choice
explicit. One shared dial can change several observations without copying its
request into every link. Both resting and farther reaches still participate,
so the original coarse V bit stays valid.

Construction names and illustrative coordinates are unavailable to the
executors. The original geometric construction source is deliberately absent.
If two retained encodings are identical, the same attached law and input must
give identical behavior. Different behavior needs a retained difference or an
explicitly different attached law.

This is an authored behavior experiment, not learned default selection or an
autonomous reconstruction of the missing generator.

## How to use it

Open [Let the structure respond](https://gojo.inklingai.ca/encoding/explorer/?layer=42).
Choose a case, select Route or Reach, and step the trial. Reset supplies a fresh
trial with one initial request; it is not a material refill operation inside
the running machine. Switching observations preserves the current request.

Try these comparisons first:

1. **Path / parallel sides:** the path continues; the parallel uses have two
   enabled departures at their starting corner, so this unselected walk holds.
2. **Y / explicit selector:** reveal either selector state to choose an arm.
   Leave it uncertain to see alternatives without committing one.
3. **Common / two reach roles:** one dial changes four linked reads in the
   first case and two in the second.
4. **Shared / independent house seams:** one adjustment affects both face
   groups only when they actually share the seam's value field.
5. **Pinned / open response:** the request remains waiting for different
   reasons—an explicit pin versus an absent response binding.

The drawing remains a schematic. Its moving highlight shows the activation;
reach highlights show which reads have become farther. The experiment does
not solve new vertex coordinates or silently stretch the illustration into a
claimed geometric result. The ordinal change is real runtime state, while
its physical distance remains unknown.

## What survives removal of the creator

Every trial first encodes and independently decodes the prior experiment's
family and use arrays. The decoded object has fresh local ownership and no
reference to its original geometric construction source. The executor gets
neither its pattern caption nor its drawing coordinates.

The output still retains its site sharing, link identities, field sharing,
selected use directions and grouping. Those are the construction's traces.
A prior generator could have left them for a reason; a later observer can use
them as evidence for a revisable default. We do not need a complete history
to make that evidence useful.

The current path-square and radial-square have identical family/use bytes
after their separate geometric bases are removed. They therefore behave the
same under the same attached laws. The parallel-side square retains different
use directions and groups. This is an important control: we must not remember
a vanished generator's label to manufacture a behavioral difference.

These are independently loaded outputs with newly attached trial mechanisms.
This pass does not dynamically delete an executing generator, erase its held
material, or claim that its previous transfer history has been reconstructed.
The family transport does not include the new trial's live activation or
adjustment state; it is not a complete machine checkpoint format.

## Route behavior: directions become an explicit hypothesis

`FamilyWalk` creates one activation site per family site and a separate input
site containing one supplied activation. Each distinct signed use becomes an
actual passage. Two groups using the same link in the same direction refer to
one passage. Different links with matching endpoints remain different choices.

The default passage permits a whole handoff into an empty receiver. Compiling
that default is an authored operational choice, not something automatically
proved by a direction arrow. The Y selector instead attaches complementary
laws to its two outgoing uses. The executor reads those law bits and references;
it has no Y, square or church branch in its code.

An **eight-byte transition law** has one bit for each of the 64 before/after
pairs of three presence bits: source S, control C and target T. The state
number is `S + 2*C + 4*T`; it is not an ODV word. A row `[source, control, target]`
selects the three actual ports. The law moves source participation to target,
or holds it, while preserving the control. No amount is stored on the passage.

The runtime tries at most one outgoing transition per pulse. If two routes are
enabled, the request stays at the junction with a conflict read. If a necessary
guard is uncertain or unavailable, it stays with that unresolved read. A
terminal with no outgoing route holds normally. Unconditional routes do not
query irrelevant controls. These cases are distinguishable in the inspector.
The route predictor's destinations describe where a resolved passage could
lead. With an uncertain selector the current executor instead holds at the
junction; the actual before/after trace records that conservative decision.

Group order still survives as evidence, but this selected walker follows
outgoing directed connections at the active site. It does not choose a face
group and secretly follow that group's order through a shared junction.
Adding such a continuation preference would require an explicit controller.

### Exact route example

For the square cycle, local runtime positions are:

| Position | Role |
|---:|---|
| 0 | Input activation |
| 1 | Guard observation |
| 2, 3, 4, 5 | Family sites 0, 1, 2, 3 |

The initial input passage is `[0,1,2]`. The four boundary passages are
`[2,1,3]`, `[3,1,4]`, `[4,1,5]`, `[5,1,2]`. Each uses the unconditional law
hex `01 00 04 00 12 20 48 80`. Packed correspondence rows retain which
signed family use supplied each passage, and its actual table/row location.

With the guard absent, packed runtime bytes change as follows:

| Pulse | Active role | Runtime byte, hex |
|---:|---|---|
| Before input | Input | `01` |
| 1 | Family site 0 | `04` |
| 2 | Family site 1 | `08` |
| 3 | Family site 2 | `10` |
| 4 | Family site 3 | `20` |
| 5 | Family site 0 again | `04` |

The family O/D/V and use bytes never change. The return is observable; it is
not a stop rule. Further pulses continue around the cycle. The survey's nine
pulses are an external observation budget, not a hidden termination condition.
The viewer's Play control similarly pauses after 48 beats. Advance can continue
the still-live machine; that display budget is not a stop law in its encoding.

An observation reversal leaves these passage laws untouched. A reversed
operational walk must be explicitly compiled from the reversed selected uses.
This keeps a change of perspective separate from a change in behavior.

## Reach behavior: a small refinement rung

`FamilyAdjustment` attaches `[field, dial, resting landmark, farther landmark]`
to every existing field. Each field has its own ordered rail
`zero → resting → farther`. These names encode order, not numerical distances.
The same local landmark number on two independent rails does not establish
equal physical extent.

The selected input follows `reserve → waiting → dial`. A local pin is attached
through `[field, dial, blocking control]`; it selects the response control
actually used by the settlement passage. An unbound response has no target
row. Pins are explicitly supplied, never inferred from a radial caption.

The field's original V remains 1 at both resting and farther positions. The
new dial bit records an ordinal refinement of that positive participation.
One field reused by four links therefore has one dial and four observations,
not four independently filled stores.

For a one-field example, the local positions are reserve=0, waiting=1,
launch=2, free-control=3, blocking-control=4, dial=5. The full byte begins at
hex `11`: the reserve and blocking-control bits are present. After an unpinned
push it is `30`: the request has moved into the dial. With a pin it becomes
`12`: the request is waiting. The blocking-control bit is a control state,
not another request included in the material count.

The accounted request always satisfies:

```text
initial request = reserve + waiting + occupied adjustment dials
```

Here each occupied site holds the whole supplied request. This is not a claim
that arbitrary nonzero magnitudes can always be counted or divided this way.
Repeated Push calls cannot create a new request. Revealing a hidden control
can retry the one already waiting.

### Uncertainty about settlement versus execution

The predictor keeps complete scope states, preserving the shared control:
`[reserve, waiting, launch, control, dial]`. Its mask has one bit per possible
whole state; the mask is a read, not another stored material quantity.

Two questions are published separately:

- **SettlementSupport:** where the request could settle after the control
  becomes available.
- **AfterSupport:** what this executor can do now. With a hidden control it
  can offer the request but must hold it at waiting.

Before a hidden-control push, scope support is hex `00000202`. Possible
settlement support is `00010400`: either waiting under the blocking control
or dial under the free control. The current conservative execution predicts
`00000404`: waiting with either concealed control state. The actual published
read agrees with that execution prediction. Revealing the free control then
permits the waiting request to enter the dial.

This distinction prevents an apparent prediction failure caused by confusing
possible physical settlement with a policy that declines to commit without
sufficient observation. No concealed bit is consulted to choose a response.

## Results and limitations

The survey covers 12 authored cases, four route-observation settings and nine
pulses per setting: **432 route pulses**. It records 230 movements, 152
conflicting-route observations, and 14 unresolved/missing-control observations.
All preserve exactly one activation and all original family bytes.

The reach survey makes **48 attempts**: two pushes in each case, with the
control initially known or hidden and then revealed. It records 20 ordinal
reach changes and 18 observations with a waiting request. Every frame accounts
for its one request; every actual scope read is contained by its predicted
execution support. The shared house seam affects both groups; the independent
roof seam affects only its own group.

See [route traces](data/construction-behavior/walks.csv),
[adjustment traces](data/construction-behavior/adjustments.csv), and the
[summary](data/construction-behavior/summary.txt). Reproduce them with:

```powershell
dotnet run --project experiments/PrimitiveMeasure -- --construction-behavior experiments/PrimitiveMeasure/data/construction-behavior
```

The tests also cover independent decoding, identical-artifact behavior,
unknown-to-known continuation, shared-use deduplication, unchanged family
state, and witnesses that cannot be rewritten through returned arrays.

This pass selects one activation at a time. It does not establish simultaneous
merge arithmetic, numeric reach adjustment, automatic geometry settlement,
learned route defaults or autonomous structural growth. Self-loop links need
an additional phase construction and are explicitly rejected by this narrow
walker; they are not silently removed. The reach rung currently requires
participating positive-right fields. General O/D changes need an explicit
basis and transfer law rather than an invented interpretation.

The useful next learning step is to retain outcomes of these small trials and
let a connected local selector use them to choose a revisable default. Its
evidence, selection and fallback routes must be part of the running structure.
The CSV analysis here is only an observer; it makes no decisions for the trials.
