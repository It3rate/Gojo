# Bounded change-triggered retry

Declared before the wake campaign. This extends PROTOCOL.md without changing its
source, comparative losses, paid-access accounting or retained review blocks.
The question is whether a coarse change can recover useful service earlier,
without buying too many extra bad predictions.

## Rule

During an ordinary retry delay, attach a native cheap subscriber to the selected
direction surface or, for the amount use, the existing grain-four amount surface.
The paid fine-use subscriber remains separate. Capture the current valid coarse
coordinate as a frozen anchor on withdrawal. This first version deliberately
anchors at withdrawal, not at the preceding forecast: a change simultaneous with
withdrawal can consequently be missed.
If withdrawal starts without a supported value, the first later valid value
establishes the anchor; it does not itself authorize a trial.

A new, valid coordinate different from that anchor arms a candidate. Confirm it
only at a second distinct resolved validation opportunity with the same current
coarse coordinate. The first change notification is not sufficient. The second
confirmation requires a bounded follow-up inspection, since unchanged coordinates
emit no second change notice. Repeated reads of one observation cannot qualify.
Missingness or a return to the anchor cancels the candidate. Restoration of an
old bad value alone cannot qualify. Do not chase changes by moving the anchor.

Allow one grant of at most two issued forecasts per completed-review-block/delay
epoch. Only an actual paid forecast consumes a token. An unavailable outcome does
not refund a spent token. Unknown input, return to the anchor or ordinary retry
eligibility cancels remaining tokens. Further changes cannot replenish the grant
within that epoch. There is no success-dependent extension of the grant.

Granting permission must not change the ordinary review's evidence, partial block,
rung or deadline. Actual subsequent outcomes enter the same retained four-outcome
block as all other paid forecasts. Only ordinary review can alter that history.
A changed value supplies a reason to investigate, not a favorable rating.

## Matched campaign

Run each trace with fixed delay two, escalating delay capped at 32, and that same
escalating rule plus the two-forecast wake trial. Use the five original fixtures
unchanged: steady-reversal, grain-gap, applicability-return, unpredictable-113 and
unpredictable-271. Controls receive the same observations and use surfaces.

Add a sixth fixture, wake-chatter, starting at 10000 and then:

- 96 increments of +1 to establish an unhelpful amount service;
- 64 increments alternating +1,+2 to cross a coarse boundary every observation;
- 64 increments alternating +4,+1 to test isolated larger changes;
- 96 increments repeating +4,+4,-4,-4 to confirm a cell immediately before a
  reversal can invalidate the next prediction;
- 128 increments of +4 to test recovery after chatter.

Names, phase boundaries, seeds, future values and expected outcomes never enter
the actor graph. Do not tune thresholds or fixtures after examining the campaign.

## Accounting and interpretation

Keep paid forecasts, initial cheap synchronizations, dormant change notifications,
scheduled revision checks and confirmation inspections as separate counts. Do not invent an exchange rate
between them or infer CPU savings from fewer paid forecasts. Report early-probe
issues separately from ordinary issues, including their later benefit, mistakes,
unknown outcomes and any still-pending promise. Track denied additional changes.

Compare partial-use benefit and recovery by phase against both controls. Report
false trials and overhead on chatter and unpredictable inputs even if recovery
improves. Check native transport, once-only advancement, physical connection
lifecycle, the two-issue allowance and unchanged negative history at grant.
Retained graph counts and cumulative allocation remain separate measurements.
Revision-only checks do not read the selected coordinate on silence. Permission
checks validate the current coordinate when a token is available; they are pure
reads, not additional observations or mutable inspection counters. These activity
counts are consequently not an exhaustive instruction or processor-cost ledger.

The source, native publication checks and local host scheduler still advance on
every arrival. This is a bounded native policy experiment, not an autonomous
asynchronous kernel, learned attention mechanism or demonstrated compute saving.
