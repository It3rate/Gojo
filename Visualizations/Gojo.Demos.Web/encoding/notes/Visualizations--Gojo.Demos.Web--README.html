Gojo Demos Web Directory

Static landing page for https://gojo.inklingai.ca/.

The production bundle mounts the browser applications beneath this page:

  • /quickdraw/ — drawing studies, starting with capital letters and church drawings at /quickdraw/line-art/;
  • /ornaments/ — ornament collections, source comparisons and native downloads; start with the collection publishing guide
  • /minds/ — captured Gojo experiments, step viewer, research notes and the experiment/development roadmap
  • /syntax/ — illustrated syntax notebook, with thumbnails, stepped examples and actual fixture source dialogs
  • /blocks/ — Gojo Blocks
  • /gears/ — Gojo Gear Demo
  • /gearLadder/ — Gojo Gear Shape Ladder
  • /sketch/ — GojoCAD SketchViewer
  • /core4/ — frozen archive of the earlier Core4, Core2 Patterns and Foom Numbers browser demos

Deploy this landing page, the four current application directories and the Core4 archive as one Static Web Apps bundle using GOJO_SWA_CLI_DEPLOYMENT_TOKEN.

The syntax notebook is a static website. Rebuild it using the script below; no browser-application build is needed for an editorial change. Run the fixture and browser checks documented there before publication.

node Visualizations/Gojo.Demos.Web/tools/build-syntax.mjs

Production deployment must include all four current browser applications and the Core4 archive. Publishing any one directory alone would remove other routes. The ignored publish-deploy-root directory is a cached bundle, not a reproducible source checkout. Its runtime manifests can differ from the live deployment even when the entry-page HTML matches. The Core4 runtime payloads are intentionally kept frozen in that cache; the tracked /core4/ index is overlaid during preparation and the preparation step fails if the archive is missing.

Prepare the syntax addition from the current public application manifests:

node Visualizations/Gojo.Demos.Web/tools/prepare-syntax-deploy.mjs

This builds publish-deploy/syntax-site, retains the live browser loaders and their resource hashes, fetches missing or changed assets, verifies compressed counterparts, and overlays the syntax directory, home page and site config. It excludes obsolete fingerprinted WASM files absent from the current runtime manifests from the staged bundle, keeping the cache and frozen Core4 archive intact. This prevents old application versions from consuming the hosting quota. It also overlays Minds and the ornament collections, so subsequent publications retain /minds/ and /ornaments/. It retains the Quick Draw study category and its selected downloads at /quickdraw/. It writes a backup and a public-asset hash manifest to the OS temporary folder. The cached smooth, performance and six-rung variants were not deployed when this gallery was added; their runtime endpoints return 404. The preparation script checks these endpoints and stops if an additional live route needs to be included. A home-page fallback is not evidence that an application exists.

After the full bundle has been assembled, use the existing deployment token through the CLI environment (never print it or put it on the command line):

Quick Draw studies

The /quickdraw/ category links to studies through the ordered catalogue in tools/quickdraw-studies.json. Each entry has a stable child route, title, description and explicitly prepared public source directory. Add further studies to that catalogue without changing existing URLs or the homepage link.

The alphabet and church inspector starts the category at /quickdraw/line-art/. Its source is experiments/quickDraw/results/line-art/public. That directory's public-files.json selection lists its entry page and native downloads; unselected research files are not copied to the site.

The church cleanup comparison at /quickdraw/church-cleanup/ shows the original drawing and saved final shape proposal for all 36 verified pilot samples, 12 per page. Its captured display is generated from the church-shape-cleanup.v3 checkpoint in the GojoQuickDraw dataset, with source archive hashes and native restore flags checked. Run tools/build-church-cleanup.py --dataset $dataset to refresh the display, then run it again with --check and rebuild the Quick Draw category. The published coordinates are rounded to one display unit; the authoritative evidence and native records remain in the dataset.

The construction study at /quickdraw/construction/ uses experiments/quickDraw/results/construction-resolution/review. It contains fourteen churches, 26 individual capitals and the alphabet atlas: 41 designs at five resolutions, 205 executed programs and 945 construction steps. The inspector contains only captured native reads; the browser neither reconstructs recipes nor invents dependencies. A lossless shared-subtree transport reduces the embedded payload, with every expanded value checked against the original checkpoint. Use tools/check-construction.cjs to verify all steps, comparison paths, retained references and native downloads. Its restored-native-construction contract verifies restored/replayed flags and selected archive links before copying.

All 205 executable archives remain available from GitHub, pinned to commit 2921c2ec6e9d8aefb9719f64be0a340d87abfd08. Their compressed and decoded hashes are recorded in quickdraw/construction/publication.json; the browser checker fetches every archive and verifies its integrity and cross-origin availability. Only clicking a download contacts GitHub. Drawing and resolution controls use the embedded captured reads. The twelve earlier construction download URLs remain available on this site alongside the 17 line-art downloads.

Primitive encoding

The /encoding/ section contains the shared-code Primitive Explorer and HTML versions of its Markdown notes. See ../Gojo.PrimitiveExplorer.Browser/README.md for build and browser checks. The deployment preparation requires a current browser publish and generated notes; it preserves the other live applications.

To stay within the existing hosting quota, preparation removes redundant .br/.gz transport siblings beneath non-archived runtime folders when the original asset is present and the compressed sibling is not named by a live manifest. Manifest-addressed assets and the frozen Core4 archive are retained.
