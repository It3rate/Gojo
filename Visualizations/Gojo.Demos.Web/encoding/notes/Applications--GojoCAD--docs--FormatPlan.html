GojoCAD Format Plan

This plan starts from the ideas in the Gojo concept-surface notes, read spine, unit-shape notes, and interpretive graphics notes. It applies them to a graphical definition library.

GojoCAD should not mimic a conventional vector-command model. It should define graphic structure in the same way Gojo defines other concepts: connected structure first, local reads second, external output later.

The lower-level recognition direction is captured in ReadAlgebra.md. That document treats discovery as a derived read graph over relation structure, where each local relation read carries evidence upward instead of every consumer testing every possible shape.

These should remain primitives or local reads. They should not be collapsed into broad enums such as shape type, curve type, or junction type.

Site Pinning And Coincidence

Equal tick values are not enough to mean that two graphic elements are joined. Two independent locations may render at the same position and still only be a crossing, overlap, or unresolved coincidence. A true joint needs shared structure: a shared TickRef, a reused point relation, or an explicit relation between the participating points.

GraphicStructure.Pin(a,b) is intentionally only ordinary Relation(a,b). It is not a wrapper object or metadata tag. It exists so sample and application code can say "these point relations are joined" without hiding the join from the read graph.

Construction helpers such as UnitShape.LinearAt(...), GraphicStructure.LinearCarrierAt(...), and GraphicStructure.CircularCarrierAt(...) avoid duplicated "start equals end" parameters when a carrier is seeded at one site. They make the construction intent local and inspectable. A UnitShape is still a crystallized basis surface, so live retargeting should be represented by an explicit pin or attachment relation when the graphic meaning is "this center follows that point."

For circular carriers, a radius attachment is also phase evidence when the attached marker is on the circle. The vector from the circle center to the base point should define that marker's local angular direction. Without that evidence, rendering may default to a horizontal-right anchor, but paths should prefer inherited local direction from the incoming segment or carrier basis.

2. Systems To Support As Local Reads

The following external systems are useful inspirations, not mandatory internal models.

System GojoCAD reading
Point grounded site on a carrier
Segment ordinary positive-face span between two point relations
Polyline, shared-frame repeated point data in one fused basis
Polyline, repeated-step repeated span/arc basis instances with explicit joins
Polygon closed polyline plus fill participation
Circle point-radial seed plus radius and contour evidence
Arc contour partition with start/end markers and optional direction
Quadratic Bezier endpoints plus one control-site relation
Cubic Bezier endpoints plus two control-site relations
Spline repeated local curve spans with continuity witnesses
Clothoid path-length span related to curvature span
Involute circle base contour phase related to tangent/unwrapped length
Branch graph shared sites, spans, lane transitions, and flow witnesses
Corner local feature site where spans meet
Rounded corner corner plus radial transition or radius evidence
Intersection co-location plus connection, crossing, pass/block, or residue read
Fill closed or bounded boundary plus area participation
Hole opposed fill participation inside a boundary

The goal is not mathematical minimalism. The goal is a structure that matches how people talk about and refine shapes.

Shared-frame and repeated-step polylines are different read surfaces, not competing truths. A shared-frame polyline repeats coordinate data against one basis and now reads as ordered coordinate groups connected by frame segments. A repeated-step polyline repeats a structural template by addition: each new step instance appends to the current path and can carry its own local length, turn, arc, radius, or curvature evidence while preserving template provenance through compatible unit descriptors. The current read graph exposes this as an ordinary open segment path with shared template provenance, not as a special polyline tag.

3. Curve Definitions Before Calculation

Many useful graphic curves can be defined without calculating all their points.

Bezier-like curve

selected endpoint span
control site evidence
parameter span
residue: unsampled positions

Clothoid-like curve

selected transition span
path-length carrier
curvature carrier
relation: length span -> curvature span
residue: unsolved placement

Involute-like curve

base circular contour
phase partition on contour
tangent or ray outlet at selected phase
unwrapped length carrier
relation: phase advancement -> tangent length
residue: unsampled path

These surfaces can later be sampled, approximated, rendered, or used as AI conditioning. The definition remains useful before that happens.

4. Branches, Merges, And Junctions

Y and T shapes should be defined by real connection:

junction site
incoming span(s)
outgoing span(s)
lane basis
lane transition evidence
read witness or residue

The same topology can read as a split, merge, branch, intersection, crossing, blocked junction, inlet, or outlet depending on flow and lane evidence. That meaning should come from the local structure, not from a stored junction tag.

5. Resolution Ladder

Graphics should support low-to-high resolution reads:

presence
rough mass or contour
feature sites
ordered spans
curve parameters
sampled points
solver/export reference

A table with rounded corners can begin as:

table-like surface
four corner feature sites
some rounded-corner evidence
residue for exact size, radius, proportions, and style

Then it can refine into edges, radii, fill, stroke, material, and exact external output references. The low-resolution read remains valid while the details settle.

6. Attribute Participation

Attribute presence should come before attribute detail.

stroke participates
stroke width unresolved
stroke width coarse
stroke width exact

fill participates
fill color unresolved
fill color family
fill exact RGB
fill material or lighting evidence

Unknown stroke width is not zero width. Unknown fill color is not transparent. Missing detail should remain available as unresolved structure, residue, or tension.

7. Near-Term Milestones

  1. Keep the current point, radial flow, segment, and directed-segment tests passing.
  2. Continue expanding GraphicReadGraph so GojoDraw and future consumers can consume carried local reads rather than flat shape tests.
  3. Add a small curve-control surface for quadratic and cubic Bezier-like definitions.
  4. Add contour partition helpers for arcs and circular phase.
  5. Add explicit fill and anti-fill format helpers over closed or bounded boundaries.
  6. Add style participation surfaces for stroke, fill, color, and width.
  7. Add resolution-ladder examples for coarse-to-fine graphic reads.
  8. Add local read witnesses for corners, rounded corners, intersections, crossings, branches, and merges.

Each milestone should prefer relation structure over wrapper classes. Helper APIs are acceptable when they only build or inspect ordinary Gojo structure.
