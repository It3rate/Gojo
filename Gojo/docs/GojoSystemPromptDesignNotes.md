# Gojo System Prompt Design Notes

This note explains how `GojoSystemPrompt.md` was derived. It is not part of the
prompt itself.

## Baseline Assumption

The Core4-oriented instruction block supplied with the task was treated as the
current prompt baseline. It contained the ten broad Core4 axioms plus the site,
pin, relation, freeze, and attachment supplement. No separate prompt artifact
was found in the repository.

## Evidence Reviewed

The replacement was reconciled against:

- the current core types and settlement code in `Gojo/Core`;
- the kernel, equation, pattern, concept-surface, CAD, and encoding tests;
- the active Gojo axioms, especially carrier settlement, duality, unit shape,
  crystallization, ports, operations, repetition, resolution, and tension;
- `GojoReadSpine.md`, `StructuralAndConceptualLadders.md`, and
  `ParticipationSettlementReads.md`;
- the ConceptSurface boundary/flow and concept-shape codices;
- current repository and project READMEs;
- the Core4 kernel, carrier-read, and boundary-overflow notes;
- `LegacyCore4IdeaInventory.md` for intentionally retained design memory.

The current full solution passed its tests during this review. The prompt does
not embed the test count because that fact is already more current than the
count in the old repository instructions and will continue to change.

## Major Replacements

| Core4-era center | Gojo replacement |
| --- | --- |
| A single uncalibrated `Measure` as the primitive | An `IElement` vocabulary centered on carriers, signed carrier locations, tick references, ordered relations, placeholders, and unit shapes. |
| The `0/0`, `m/0`, `m/u` ladder as the general relation state | Open placeholders/bindings, frame projection with explicit residue, carrier tension, boundary-flow legality, and witnessed reads. The old ladder remains lineage, not the canonical runtime representation. |
| Origin, pin, freeze, basis, and attachment as an assumed construction sequence | Point and segment relations, explicit exposed ports, stable unit shapes, calibration/read surfaces, and crystallization. These can express the useful stages without reintroducing the removed wrapper ontology. |
| Four observer modalities as a foundational taxonomy | Local projection, settlement, operation, focus, transform, generation, and inspection surfaces whose role comes from relation shape and read context. |
| Opposed units as the ordinary source of negative scalar values | Signed locations on one carrier for scalar negation; opposed carrier faces for distinct flow participation; reversed relation order for traversal. |
| Fused two- or four-value structures as the general dimensional representation | Relation-shaped ports and groups, directed segments, product unit shapes, orthogonal outlets, participation settlement, and concept surfaces. |
| Self-fusion as a special power mechanism | Visible repeated product participation plus `RepeatSurface`, controller, feedback, residue, and timeline. |
| Boundary overflow as a broad future route layer | The executable carrier settlement foothold plus the newer boundary-flow chain: projection, lane basis, accepted/blocked transfer, target-local/shared capacity, target settlement, and timeline. |

## Site Supplement Terminology

The older site-relation supplement contained useful construction intuitions,
but its `0/0`, `m/0`, `m/u` state ladder is not the current Gojo core. The
replacement treats its terms as contextual verbs and reads:

| Older term | Gojo reading |
| --- | --- |
| site | A referencable `CarrierLocation`, point relation, shared `TickRef`, placeholder, or exposed relation site, depending on resolution. |
| pin | Select or share the exact site structurally; do not create basis meaning merely by naming it. |
| relation | The active ordered `A -> B` primitive. |
| freeze | Stabilize tick grammar or reusable structure through `UnitShape`, crystallization, or an exact stable surface. |
| basis | A relation-shaped frame, unit shape, lane basis, or resolution surface through which a source is read. |
| attachment | A live relation, binding, port, or output connection between actual sites and an exposed basis. |

This keeps the useful warning that selecting a site, relating it, stabilizing
the relation, and reading live participation through it are different acts. It
does not restore the removed wrapper types as the kernel ontology.

## Core4 Ideas Retained In Gojo Form

Several Core4 intentions remain important after changing representation:

- meaning should be numeric, inspectable, and structurally traversable;
- unresolved states are information rather than invalid math;
- relation shape should replace symbolic operation dispatch;
- stable structure may crystallize into a reusable unit;
- boundary crossings may route, wrap, count, branch, filter, or remain tension;
- live observations must not automatically drain their sources;
- repeated structure and intermediate states must remain visible;
- equal visible answers can retain different structural provenance;
- a system should lower locally visible tension rather than demand one global
  final solution.

The replacement prompt keeps these as Gojo rules while avoiding direct reuse of
Core4 wrappers, same-lineage carriers, fold machinery, or ratio-state ontology.

## Important Reconciliations

### Immutable Versus Dynamic

The earlier prompt broadly preferred immutable structures. Current Gojo has
deliberately mutable carrier value/tension and retargetable tick references,
while unit shapes and crystallized promises are stable. The new prompt narrows
mutability to physical state sites and keeps witnesses, unit shape, and
snapshots stable.

The October connection-assembly audit exposed an implementation mistake in how
the earlier reconciliation was applied: a small live network was surrounded by
a freshly rebuilt complete calculation witness on each arrival. Keeping a
promised historical witness stable does not require rebuilding live constraints,
equations or connection identities. The prompt now says this explicitly.
Adaptive current state may move while selected historical coordinates remain
fixed; exhaustive provenance is a chosen inspection contract, not the default
definition of a Gojo observation.

Core now exposes explicit local attachment withdrawal and read-only live
attachment inspection. Withdrawal preserves all carrier state, including held
tension and a receiver's last published level. It is not an inverse material
transfer. Reattachment can settle the retained relation against current input.
Automatic growth, usefulness selection and decay remain separate directions.

### Tension Versus Residue

Some historical notes use tension for nearly every unresolved quantity. Current
Gojo distinguishes read residue from transferred unsettled change. The new
prompt requires residue to become carrier tension only when a transfer, import,
or settlement would otherwise lose incoming participation.

### Code Versus Direction

Current code is authoritative about what works now, but it is intentionally a
foothold. Active Gojo axioms remain relevant for requested extensions. The new
authority section therefore requires status labels instead of either freezing
the code as the final ontology or treating speculative notes as implemented
law.

### Higher-Level Helpers

Gojo now contains many named helper surfaces. The prompt does not ban them. It
requires their fields to remain ordinary connected Gojo elements and their
readers to be local. This preserves the practical read spine without making
helper classes the semantic source.

### Summary Enums

Boundary and flow code has compact summary records and enums, while its newer
construction path preserves primitive face, side, lane, and transition
evidence. The prompt allows enums as projections and diagnostics but rejects
them as canonical meaning.

## September 2026 Syntax And Local Exploration Clarifications

The syntax review and the user's response clarified several foundational
distinctions. Partial construction is positive structural participation rather
than a lesser form waiting to become valid. A goal or claim can retain the
reason a local space focuses its exploratory work there.

Candidate preservation must not presume a final winner. Local spaces may
combine and filter contributions and retain several useful structures. The
current first-binding convention is not a proposed learning law. Likewise,
claim mismatch is conditional evidence about a statement, not an assignment of
fault to its expected output. Exact arithmetic remains valid and independently
testable; uncertainty concerns operands, applicability, resolution, and the
connected premises. Wider utility and support are intended feedback mechanisms,
not a global verifier or an implemented confidence policy.

The earlier immutable-versus-dynamic reconciliation remains appropriate for
stable tick promises and declared exact snapshots. It must not imply mandatory
permanent archival history. Adaptive memory may deliberately compress, revise,
or forget through visible transformations, with a narrower retained promise.
Similarly, connection participation and utility should eventually support
growth, decay, redirection, and pruning. The prompt labels these as direction;
the new local blend fixture supplies a small explicit experiment, not these
general mechanisms.

Source-space identity remains a direction grounded in exposed references and
correspondence. It does not authorize merging coordinate-equal sites or
compatible carriers. The current implementation still distinguishes carrier,
point relation, shared TickRef, and coordinate equality.

See [the updated syntax review](GojoSyntaxReview-2026-09.md) and
[the executable local blend fixture](GojoLocalBlendFixture.md).

## September 2026 Mathematical Conformance

The low-level audit found that ratio projection placed a scaled division
remainder on the source carrier without converting its basis. The correction
requires fractional source remainders even though the target read is integer.
The canonical projection axiom now states the reconstruction law explicitly.

`L(source,n) -> P(source,d)` supplies the subdivision numerically in ordinary
Gojo structure. Its residue reader is contextual and narrow. It does not add a
fraction tag, change carrier storage, or pretend general denominator-unit
cancellation has been implemented. Whole-tick imports reject these fractions
before applying collected slot changes. Observation, including follow and
boundary projection, keeps the exact structure. A later material refinement
mechanism can extend admission without changing arithmetic.

The positive-resolution rule prevents invalid authoring and saturated products
from altering a stable tick promise. Wide temporary arithmetic in projection,
structural ratio scaling, and operation accumulation fixes avoidable host
overflow while retaining checked limits for stored coordinates and fractions.
The prompt requires accounting and range discipline without claiming every
experimental reader supports arbitrary-precision inputs.

The conformance fixture exercises exact mathematics independently of a live
learning network, then checks composition through syntax, resolution and
material boundaries. This preserves the user's distinction between correct
local mathematics and uncertain applicability of connected premises. See
[mathematical conformance](GojoMathConformance.md) for coverage and remaining
low-level laws; general feedback discovery remains later work.

## Explicit Dimensional Reads And Standards

The user confirmed that ordinary dimensional products can admit commutative
reads while preserving the authored order and history. Their examples, mph and
litres/100 km, also require preserving the selected calibration. The canonical
unit axiom now records this distinction; it does not make primitive relations
or default unit compatibility commutative.

The first [unit quotient surface](GojoUnitQuotientReads.md) connects ordered
numerator/denominator factor groups with the selected standard. Its explicit
cancellation witness pairs equal native tick shapes once per occurrence and
preserves unmatched and open factors. This is a bounded dimensional read, not
a new general reciprocal UnitShape or numeric division engine. Keeping the
known mathematical law separate from material conversion and domain conditions
lets the next implementation step remain concrete and reviewable.

The prerequisite product reader correction removes framing from factor
inventories while keeping additive and opposed factors whole. It changes a
faulty read, not the original stored product order or nesting.

## Quotient Tick Promises And Numeric Observation

The next step keeps syntax and kernel together. `quotient_unit(expression)`
selects the checked `UnitQuotient.TryReadUnit` read. It captures the ordered
native factor surfaces and standard provenance into an immutable `UnitShape`.
Its algebra is an ordinary three-field ordered group on the neutral holder:
numerator unit surfaces, denominator unit surfaces, and a descriptor slot for
the standard. No inverse flag or operation opcode is added. Standard provenance
uses the existing descriptor mechanism; names and runtime carrier values do
not define conversion. Empty groups supply explicit absence of dimensional
participation instead of borrowing the wildcard atom as a multiplicative one.

The capture preserves unreduced order. A caller can separately select a
cancellation witness's result for another stable promise. Composite quotient
factors remain whole in product and additive inventories. The same check exposed
an additive-inventory bug that split an opposed factor; that reader now also
preserves the opposed wrapper and its source together.

`QuantityQuotient` connects two samples, output basis, and standard, then uses
the existing affine projection law with the denominator attached as evidence.
This is a local observational read, not a material divider or general equation
dispatcher. Known zero, open samples, and mismatched native output promises
retain an open result and their participants. The constructor spelling is gone
after parsing; the selected context and connected fields remain.

The native quotient basis deliberately does not infer calibration conversions
or flatten nested quotient expressions. Refinement remains an explicit next
projection, with its residue in quotient ticks retained alongside the earlier
division residue in numerator ticks. Syntax tests exercise that reconstruction
and partial binding as well as fully constructed reads. See
[the implementation and boundaries](GojoUnitQuotientReads.md).

## Numeric Structure Milestone, September 6, 2026

The next checkpoint makes three earlier boundaries executable without changing
the distinction between dimensional reads, calibration and material movement.
Nested quotient expansion retains a decomposition witness for each source
factor and its standard. Reduced numeric observation separately checks the
division domain before selecting an exactly equivalent output basis.

Subdivision uses `S(Unknown,0,n) -> source-unit-surface`, opposite the placement
of a coarse resolution frame. This expresses a scale correspondence using the
existing primitive relation. Positive packets through two zero-origin frames
permit explicit refinement, coarsening and borrowing with exact conservation
and visible shortage. It does not specify automatic route choice, fairness or
distributed confidence. Resolution had dropped opposed faces; preserving them
is a correction to the earlier promise, not a new sign convention.

`GojoNumericFormat` restores complete integer-table graphs, including partial
patterns and live attachment ownership. Construction hooks link frozen units
and cyclic references before roots become visible; loading never calls public
settlement entry points. New runtime identities isolate the restored world,
while their relative source ordering preserves current settlement tie-breaks.
This is an explicit independent-world contract, not persistent identity across
separately loaded packets. The byte format is versioned but not a canonical
text writer, compressed memory, runtime closure serializer or global history.

Raw `TickRef` unit descriptors previously allowed a stable promise to drift.
They now require grounding in a location before capture. Validation also
rejects writable aliases into frozen unit internals and inconsistent cached
opposite-unit pairs. Exact claim, fit and follow scalars now check overflow;
unreadable comparison residuals no longer appear as zero error. These changes
protect the mathematical premise without assigning global fault to a participant.

See [the full review](GojoNumericMilestoneReview-2026-09.md),
[refinement](GojoMaterialRefinement.md) and [numeric format](GojoNumericFormat.md).

## Uncertainty Reference, September 6, 2026

The user's nominal-bolt, planned-clearance, ignored-detail, desired-goal and
same-cup examples expose several distinctions that a single uncertainty field
would erase. The prompt now separates evidence about possible states, selected
perspective, and permitted or desired conditions. A tolerance alone does not
prove a part conforms, and a desired gap need not be an equality violation.
Known residue or unsettled change can be numerically exact.

Dependency belongs to the connected source, state, observation and shared
causes. Reusing a category does not identify its instances. Conversely,
distinct observations can share a calibration cause, while two observations
of one object can still have separate event-specific errors. The same finite
quantity can cancel against itself under valid domain conditions; losing that
relation in two independent error bars would weaken a justified read. Feedback
routes also need enough provenance to avoid treating echoes as independent
evidence. Deliberate compression can weaken the promise, but cannot retain an
unsupported stronger claim.

These are design guardrails, not a newly implemented uncertainty evaluator.
`StructuralPattern.IsComplete` concerns binding; a completely constructed model
can remain uncertain. Existing nominal resistor/tolerance surfaces provide a
useful precedent but no general interval-propagation or conformance law. The
older crystallized-resolution note now identifies coarsest-basis selection as
a granularity heuristic and distinguishes first-order product sensitivity from
a guaranteed error bound. No runtime arithmetic was changed for this review.

The [uncertainty reference](GojoUncertaintyReference.md) is an open inventory of
overlapping circumstances, not a primitive taxonomy or an alternative prompt.
It recommends beginning the next bounded-quantity fixture with shared causes,
observation identity, normative versus evidential bounds and domain refusal,
so dependence is present from the start. Selection of experiments, confidence
updates and distribution of response remain policies to develop separately.

## Bounded Quantity Fixture And Opaque Sources

The user's follow-up clarifies that approximation can actively direct attention
away from detail, even when finer information is known. The fixture uses an
explicit coarse focus with a retained fine complement; it does not infer
importance from decimal places or define one universal meaning for "about."
The same known discrepancy can be acceptable under one tolerance and exposed
again by a stricter question.

External sources can remain black boxes. Shared variation and historical
utility may eventually support learned weighting, coalescence and atrophy.
The prompt does not demand unlimited ancestry research or require external
sources to expose all their dependencies. Exact slot identity and a learned
similarity claim must still support different calculations. An external
dependency service could supply correspondence through the same port model.
No such learning or source-tracing mechanism is implemented by this fixture.

The first arithmetic foothold uses a local sample slot connected to a support
span and evidence, then calibrated through ordinary source/target frames.
Repeated slots combine before bounding. All their domain constraints are
checked, including those whose final gain becomes zero. Temporary rational
coefficients are a derived backend; the reader emits shared slots, intersected
supports and frame calibrations as a new ordinary affine surface with its
source attached. This is not a tagged symbolic expression tree or hidden
dependency registry.

Combination uses additive port topology. Product and quotient retain their
inputs and produce conservative bounds, with a selected same-function square
and a nonzero-domain quotient identity. General nonlinear dependency refinement
is deliberately not inferred from those enclosures. Conformance calculates
nonnegative distance to a permitted span, leaving acceptability separate from
quantity truth and causal fault. Exact endpoints and outward rounding excesses
remain visible; no observation introduces carrier tension.

The [fixture document](GojoBoundedQuantityFixture.md) describes these laws and
their syntax. The authored goal example separately invokes existing material
transfer and records its witness on a timeline. This demonstrates a chosen
response, not automatic allocation or a convergence guarantee.

## Contour-Grounded Rotation And Local Interfaces, September 8, 2026

The CAD/ECAD assessment initially gave matrix composition too prominent a role
in the proposed rotation work. The user clarified that rotation must arise
from internal connected construction, including the existing point-orthogonal,
contour, radius and calibration direction. Axiom 11 now makes the distinction
explicit: angle units and matrices can read or implement a grounded turn, but
cannot become its sole source of meaning. This clarification follows the
potential-shape and structure-through-tension notes; it does not establish a
new geometric law or claim the complete rotation mechanism already works.

The source review found executable circular provenance, attachments, cycle
accounting, perimeter projections and syntax restoration. It also found that
these do not yet establish a general contour-to-pose or rigid-turn executor.
The ordinary orthogonal outlet must remain broader than a metric right angle.
Live pivot correspondence is separate from frozen unit provenance. The
[follow-up review](GojoContourRotationAndLocalInterfaces-2026-09.md) records the
evidence, unfinished Blocks examples and proposed construction sequence.

The user's layer and mating examples reinforce the existing composition rules:
local spaces can expose only the interfaces relevant to their neighbours, and
another local space can select their combined relation. A stricter request can
expose uncertainty or response shortfall without assigning global fault.
Any material response still uses explicit tension/settlement or structural
retargeting. GojoEcad remains exploratory evidence; its specific representations
need not constrain a better Gojo construction.

## Circle Construction Before Coordinate Landmarks

The first rotation fixture still began too late: it supplied X/Y coordinates,
a metric and radial landmarks, then derived a valid turn between them. Passing
those tests did not establish the earlier circle or landmark construction.
The user's correction specifies point -> orthogonal possibility -> common
offset path -> attached radius/reference -> closed whole -> partition.
Axiom 11 now makes that ordering explicit. It also separates radius measure,
native circumference fractions and a later arc-length/radius calibration.

The [native circle fixture](GojoCircleConstructionFixture.md) records the
offset's open common reach, binds a native radius, connects closure to the
actual start site and applies explicit subdivision to the whole. Markers and
equal-reach radial attachments can then be derived without an X/Y grid. The
selected homogeneous planar offset and equal subdivision are construction
contracts, not discovered field behaviour or an automatic metric solver.
The earlier coordinate fixture remains a later, supplied-geometry experiment.

In that earlier fixture `$anchor` named a newly created relation to an exposed
coordinate representation. It was not a pre-existing contour site. Renaming it
to `$centre_representation` and showing the earlier construction prevents its
role from being mistaken for a primitive anchor in the world.

## Justified Affine Bases And Observer Orientation

The user clarified that Cartesian-like coordinates are a useful possible
outcome of Gojo construction, not an approach to avoid. The requirement is to
justify and stabilize the basis. Partial coordinates, omitted points and
different signed conventions can then share ordinary affine constructions.
The earlier three-point parallelogram fixture used an existing coordinate
basis; it did not establish one from three arbitrary observed points.

Axiom 11 now separates basis construction, selected model applicability and
observer orientation. A direction and its opposite need no universal up/down
meaning. Rotating a drawing or viewing it from the back changes its observer
read. It does not swap carrier faces, reverse a relation or retarget a site.
Orthogonal remains unaccounted participation in the current order, including
the remainder of a partly accounted signal; a rendered right angle is only
one useful illustration.

The [grounded affine fixture](GojoGroundedAffineBasisFixture.md) selects a
linear participation through a native segment's orthogonal outlet, attaches
their origins, captures both ordered spans and exposes explicit native-to-unit
calibrations. The affine product law is the selected construction context;
this is not a discovered physical independence or metric proof. The existing
six-edge Bézier procedure consumes the established basis without new curve
opcodes. Kernel checks and a view-changing demo keep arithmetic, uncertainty,
opposite conventions and presentation as separate concerns.

## Complex Arithmetic As A Selected Interpretation

The user's September 11 clarification restores complex arithmetic as an
important Gojo interpretation without making it the mandatory meaning of all
opposed participation. The older model's two-slot complex algebra was broader
than the current fused-face product, which has a different selected law.
Silently changing that existing product would conflate useful interpretations.

Axiom 10 now explicitly permits both an opposed-face phase construction and
a contour-grounded construction. The existing flow codex already gives
`PF -> PI -> NF -> NI -> PF`; the added coefficient reader makes the action
and its signed unit states explicit in ordinary relations. A face dual alone
returns after two applications, whereas the imaginary generator returns after
four. This distinction supports the user's positive-on-both-faces view without
changing primitive duality. A single scalar fold is a lossy read of the pair.

The [complex interpretation fixture](GojoComplexInterpretations-2026-09.md)
checks both constructions against common arithmetic and against independently
applied contour rotation. Rational coefficient results, exact square-root
alternatives, partial root equations and separate reference-based selection
are implemented. General algebraic root isolation, analytic branches and
continuous branch following remain future work. The prompt records the
structural rule, not a promise that every fractional-power read is solved.

## Finite Calculation And Deliberately Coarse Services, October 2026

The user's follow-up makes finite arithmetic a selected Gojo capability rather
than only a presentation step after an exact calculation. A receiver may ask
for a limited useful result, and a supplier may deliberately expose a coarse
service even when it has finer information internally. The prompt now permits
finite equations with connected capacity, quantum, rounding and clipping laws.
It does not require hidden arbitrary-precision calculation followed by a
display conversion, or automatic precision escalation when information is
discarded.

This is a separate arithmetic contract. Existing exact projection, enclosure,
unit scaling, numeric transport and material transfer retain their stated laws.
Their checked range rules still prohibit silent saturation. Finite observations
can clip and qualify information; a material transfer still has to account for
accepted, blocked and remaining participation. Read loss alone does not inject
carrier tension.

The [finite-read fixture](GojoFiniteReadFixture.md) supplies a small implemented
surface using ordinary native structure. A bounded whole supplies the capacity,
including zero, and a positive quantum supplies the selected granularity. A
qualified observation connects a frozen nominal result, lower and upper support,
the finite scope, excluded loss and equation provenance. Under this reader only,
an open endpoint exposes a discarded or clipped tail. It does not revise the
closed-support grammar of `BoundedQuantity` or reinterpret arbitrary placeholders
as numeric infinities.

Publication truncates toward zero at the chosen quantum and exposes a
conservative rounding cell without retaining the exact remainder. Addition,
subtraction and multiplication consume published observations using guarded
finite arithmetic. Saturation leaves its appropriate support tail open rather
than promoting to a wider calculation or claiming a recoverable exact error.
Subtraction of the same observation retains its shared identity and cancels;
separate observations with equal nominal values do not supply that identity.
No statistical independence, probability or confidence law follows from their
separate construction.

The published reader bypasses reevaluation of the supplier's live calculation.
A threshold comparison consults only the exposed support, leaving its result
unresolved if that support cannot settle the question. Source correspondence
and provenance make the service inspectable without authorizing consumers to
traverse private supplier state in search of a finer answer. Introspection
discovers the exposed ports and their promises. More precision requires an
explicit query through an advertised route; a deliberately limited service need
not offer one.

The earlier resolution instruction required retaining refinement residue too
broadly. It now applies to reads that promise recoverable refinement. A lossy
finite read can keep a preimage, support or open loss surface instead of the
exact discarded complement. Known retained residue, uncertainty introduced by
publication, uncertainty of the original observation and statistical confidence
remain different reads. Coarse publication can direct attention or reduce
computation without implying that the supplier lacked a finer value.

The wider direction is to construct the smallest adequate local calculation,
with only the queries, connections and information needed at the receiver's
chosen resolution. General demand-driven circuits, compressed execution lanes,
automatic resolution selection and mutation are future work. This fixture is
opt-in; it does not switch the phototaxis experiment or every Gojo equation to
finite arithmetic. The canonical prompt describes the arithmetic and interface
rules, while the fixture documents its concrete implemented scope and tests.

## Prompt Shape

The final prompt deliberately has four scales:

1. canonical low-level elements and executable arithmetic;
2. operational axioms for reads, settlement, units, orthogonality, and
   crystallization;
3. subsystem composition through ports, boundary-flow routing, witnesses,
   repetition, transforms, and ladders;
4. repository boundaries, workflow, tests, and maturity guardrails.

This lets an agent work on `Carrier` settlement, a concept-surface route, a CAD
refinement, an encoding experiment, or a renderer without switching to a
different source of meaning.

## Repository Distribution

The canonical prompt lives at `Gojo/docs/GojoSystemPrompt.md`. The repository
root `AGENTS.md` is intentionally a small bootstrap that requires agents to
read the canonical prompt completely before substantive work. Keeping the
large prompt out of `AGENTS.md` avoids the default project-instruction byte
limit while preserving one source of truth.

Both files should be committed with the repository. Any machine that clones or
pulls the repository then receives the prompt and its automatic bootstrap
without a per-machine copy or configuration step. Changes to foundational
rules should update this design note in the same commit as the prompt.

`GojoChatGPTPersonalization.md` is a compact, globally scoped companion for the
ChatGPT Personalization field. It omits repository operations and is not an
alternative authority for repository work; the canonical prompt remains
`GojoSystemPrompt.md`.
