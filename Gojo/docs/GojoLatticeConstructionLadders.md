# Lattice construction ladders

This experiment retains the actual simpler construction inside each later
construction. It distinguishes asking **which structure was used as a basis**
from asking **what the current incidence supports**. Those questions can return
different useful answers without either becoming an annotation on an SVG.

The [interactive gallery](../../experiments/QualitativeFrieze/results/lattice-ladders/gallery.html)
walks 19 related constructions. The
[single sheet](../../experiments/QualitativeFrieze/results/lattice-ladders/overview.html)
shows the branches together. This is an implemented experimental layer above
the kernel, not a complete derivation of the 36 Bourgoin atlas entries.

## What is connected

Every rung contains a complete native `UnitArrangementProgram`. It also retains
the previous rung and its actual source program, selected focus, carried
complement, replacement, correspondence, blocked and open participation, and
native transition evidence. Its ordered surface is:

```text
(source -> focus) ->
  (carried -> (replacement -> (result ->
    (correspondence -> (blocked -> (open -> provenance))))))

noninitial provenance = actual previous rung -> native transition evidence
```

The initial result is the square starting program. The source group is empty;
the program and its identity correspondences remain present. Later rungs retain
that same actual basis rather than another program with a matching name.

The program supplies paths, landmark ports, closed-path declarations and
qualitative motion words. Repetition and disposition are separate native
periodic structure: two cycle directions, a finite sampling window, and seam
contracts between exposed roles. Word repetition carries participation; there
are no measured lengths, coordinate carriers or scalar angles in the saved
construction. An optional display basis selects screen proportions at the
renderer boundary.

This follows the source/focus/result/correspondence spine of
`Gojo/Structures/StructuralLadderSurface.cs`. That surface currently uses numeric
carrier holders. `QualitativeLatticeLadder` adapts the same spine with ordinary
relations and placeholders rather than adding a numeric holder to this
pre-numeric experiment. It does not change the core ladder implementation.

## Small construction laws

| Transition | Native evidence | Promise and limit |
| --- | --- | --- |
| Motion substitution | Actual source moves, selected substitutions, mapped words and path/port receipts | Reuses an instruction across a focus. Does not automatically preserve right angles or regular-polygon metrics. |
| Path refinement | Actual source chords, replacement words, endpoint/net-displacement checks and path correspondence | Preserves the selected endpoints. A bend need not remain a straight line; new interior landmarks need explicit publication to communicate between units. |
| Focused path edit | Actual selected paths, carried paths, introduced paths and complete replacement ports/closed declarations | Changes topology explicitly. A brick bond cannot be certified as an unchanged four-sided grid. |
| Assembly | Transformed and translated copies with native construction receipts, joined through exposed contact roles | Allows a larger repeated unit. A basket arrangement is more than moving an existing brick joint. |
| Field connection | Offered roles, legal displacement, accepted/blocked seam witnesses and graph quotient | Only accepted seams establish shared sites. Coordinate coincidence never creates a join. |
| Ancestor question | Actual earlier program connected through the rung chain | Returns that actual program and a witness. Does not certify every ancestral property of the current result. |
| Crystallization | Independently identified current program, external correspondence and explicit loss witness | Can forget construction history while preserving current execution. Cannot reconstruct the exact forgotten path of edits. |

The builders are executable readers over these connected surfaces. The exact
transport reader follows the declared previous-rung link and replays its native
instruction. It does not search arbitrary nested groups for something that
resembles a ladder. A replay must agree with the retained result and preserve
declared input aliases; a relabeled source or fabricated output is rejected.

## Branches implemented

| Cases | Construction | Relationship to the atlas |
| --- | --- | --- |
| L00–L04 | Square grid → stretched rectangles → intermediate course → staggered joints → oblique bond | B01/B19 families. Stretch and course insertion precede an actual joint edit. |
| L05–L08 | Sheared grid, third-family ties, crossed ties, stretched crossed network | B15–B18 families. A coarser grid can coexist with finer triangular or diagonal participation. |
| L09–L10, L18 | Paired narrow strips, oblique ribbon mapping, tighter ribbon spacing | B07/B08 families; no curve law is inferred. |
| L11–L12 | Expose inset landmarks, replace corners with chamfers | B06 family with diamond gaps. This is distinct from B06.B's upright square gaps. |
| L13–L15 | Expose long-side landmarks, assemble alternating quarter-turned rectangles, shear the assembly | B02 family. Square gaps emerge between the rectangles rather than being separately drawn square motifs. |
| L16–L17 | Wider shear and opposed brick shear | Small nearby variations using the same native instructions. |

These are construction-family correspondences, not certified graph identities
with the historical engravings. Honeycombs, sliding triangle/hexagon families,
stars, serif-I interlocks and knots remain future derivations. The gallery
includes an explicit coverage table rather than pretending every atlas entry
has already been reduced to this ladder.

## Historical basis and present evidence

The default three-by-three execution answers **38 ancestor questions** across
the 19 constructions. Each answer is checked by native identity after the
combined ladder/program archive has been imported. The current program in the
ladder is also the actual motif referenced by the repeated program. There is
no parallel saved history that merely describes another generator.

For example, L04 returns the actual L01 rectangle and L00 starting grid through
its chain. Its present graph, however, has staggered T-junctions and does not
demonstrate the ordinary grid commutations. The basis question is cheap and
exact; a present-shape question still requires evidence.

Current recognition receives a fresh publication of the executed graph's
incidence and qualitative headings, without recipe labels or historical
rungs. Three explicit, non-draining resolutions are available:

1. **Drawing histories:** preserve every actual stroke occurrence, even when
   several histories traversed the same support.
2. **Incidence support:** coalesce compatible headings only over the same
   already-shared endpoint pair. Retain every source stroke and reversal in the
   many-to-one correspondence.
3. **Straight strands:** contract degree-two sites only when native heading
   evidence establishes opposite-ray continuation. Carry the ordered incidence
   uses and suppressed sites. Corners, branches and crossings remain visible.

The source graph is never mutated by these questions. Neither equal render
coordinates nor similar qualitative quadrants justify a new connection.

On L06, a two-channel grid candidate has nine demonstrated commutations and
nine residual strokes. A three-channel candidate has 21 commutations and 18
triangles with no residual strokes. This is the intended coexistence of a
coarse basis and a richer current reading, rather than a forced single noun.

There is also a useful counterexample. L11 and L13 visibly refine straight
sides, but new intermediate landmarks are not automatically shared across
neighbouring copies: refinement preserves the existing published port roles.
The current one-pass support reader therefore retains competing continuations
instead of recovering a clean grid. It coalesces before contracting strands;
some coincident coarse spans only become available after contraction. Another
explicit support pass or a whole-span contact agreement is a next experiment,
not permission to merge equal coordinates. Their exact ancestry still works.

Candidate tables retain residue, competing continuations, finite boundary
obligations, unsettled sites and unsearched proposals separately. The current
capacity bounds candidate proposals, not total graph-processing time.

## Deliberate forgetting

L05's current sheared grid is copied into a fresh frame and standalone initial
rung. The repeated field is rebuilt with fresh bindings, periods and seam
contracts. Traversal verifies that no participant from the old ladder is
reachable from the standalone packet. The external loss witness is saved
separately and intentionally retains the correspondence to what was forgotten.

The standalone program executes independently. Its exact old-ancestor question
is open. A fresh current-incidence question nevertheless recovers a two-channel
grid with nine commutations, zero residue and zero competing continuations.
That recovers an organization, not the lost construction history, original
source identity, square metric or screen proportions.

Crystallization here is an explicit option. The ordinary ladder retains all
earlier programs, and equal-looking results may continue to have different
histories. This experiment does not decide automatically when history is no
longer useful.

## Execution and verification

```powershell
dotnet run --project experiments/QualitativeFrieze -c Release -- --lattice-ladders

# A separate output and finite sampling window:
dotnet run --project experiments/QualitativeFrieze -c Release -- --lattice-ladders --samples 2 --output artifacts/lattice-ladder-small

dotnet test Tests/QualitativeExecution.Tests/QualitativeExecution.Tests.csproj -c Release --filter "FullyQualifiedName~LatticeLadder"
dotnet test Gojo.slnx -c Release
```

Each construction is saved as a compact native gzip archive, imported, read by
the exact ladder contract, and executed before rendering. The saved roots
contain only relations and placeholders: zero carriers or carrier locations.
The 19 compressed construction packets total about 277 KiB. The expanded
question/evidence packets total about 38 MiB: retaining detailed execution and
recognition witnesses currently costs much more than retaining the generators.
These are storage observations, not a compute benchmark or a minimal encoding.
The default valid executions have zero blocked interior seams and zero open
interior seams. Finite-window frontier obligations remain separate. A false
offered neighbouring-role contract produces six blocked seams; the rejected
connection is shown with its native witness.

Twenty-three focused tests cover exact transport/replay, actual ancestor
identity, independent crystallization, source separation, native seam execution,
support coarsening, reversed drawing histories, degree-two continuation,
nonjoining crossings, open inventories, bounded search and false reads.
`diagnostics.json` records the executed counts; `verification.json` records
the completed solution and browser checks.

This is evidence for a reusable encoding and a useful ladder of questions.
It is not yet an autonomous lattice inventor, a complete ornament recognizer,
an aesthetic score, a universal affine solver or a mechanism that proves all
later patterns are strict refinements of their historical basis. The next
useful steps are explicit span-level agreements, further triangular and
hexagonal construction branches, and bounded proposals that change one native
instruction while preserving the accepted and blocked evidence.
