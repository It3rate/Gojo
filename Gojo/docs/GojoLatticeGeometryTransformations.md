# Changing the lattice geometry

This continues the [hundred-lattice baseline](GojoLatticeCatalogue.md) with
actual edits to its spans, contours and route pairing. Connection changes,
different interpretations and aspect-ratio variations were useful baseline
experiments, but did not by themselves provide enough geometric variety.

The new [transformation gallery](../../experiments/QualitativeFrieze/results/lattice-transformations/gallery.html)
pairs whole-pattern before and after views. The
[overview](../../experiments/QualitativeFrieze/results/lattice-transformations/overview.html)
compares the final unfilled scaffolds, and the
[construction strips](../../experiments/QualitativeFrieze/results/lattice-transformations/construction-strips.html)
retain every displayed native rung.

## The edit must change actual participation

`LatticeGeometrySurgery` selects actual source paths and chords. Its native
instructions and receipts remain connected to the old and new programs.

| Operation | Native promise | What changes |
| --- | --- | --- |
| Profile a chord | The replacement chain has the same formal endpoint displacement as the actual selected chord | Straight support becomes shoulders, teeth, diagonal points, staircase returns or narrow-neck bulbs. |
| Reverse the corresponding boundary | Reverse chain order and invert each ordered chord | Opposed uses of a shared side describe the same new boundary, rather than two incompatible offsets. |
| Publish fine landmarks | Carry current path identities and expose their new actual endpoint roles | Neighbour connections can negotiate the newly created vertices. This step can change connectivity without changing the drawn contour. |
| Cut a span | Native decomposition and suffix-start reads retain the old path, removed gap and surviving fragments | Support disappears; old closure claims are withdrawn where necessary. |
| Remove a divider | Select actual paths and withdraw their publication roles | Adjacent chambers can become a larger open reading. |
| Fuse two runs | Actual selected parallel chord occurrences approach and leave one declared shared interval; old endpoints remain accounted for | Two routes acquire a shared middle passage and actual branch sites through accepted public-role agreements. |
| Retarget a hub | An explicit focused path replacement relocates the common start and adjusts incident first/last displacements | Internal chamber divisions move while carried outer participation and contour closure remain readable. |
| Conform an offered contact | Refine a span at an actual offered landmark, prove its endpoint sum, then explicitly publish the new role | An endpoint-on-span or partial shared boundary can become an authenticated contact instead of merely coincident ink. |

An endpoint-preserving refinement does not preserve every property of the
earlier line. Conversely, removing a path is not a failed refinement: it is a
different edit with its own selected, carried, introduced and withdrawn
participation. All previous programs remain available as actual ancestors.

## Where the designs come from

The generator takes ten baseline families and applies ten combinations of
these local edits. The source families are paired boxes, chamfered cells,
keyed cells, stepped courses, honeycombs, three-chamber hexagons, stars,
returning ribbons, nested diamonds and basket assemblies.

The profile operations are broad shoulders, pointed shoulders, repeated teeth,
alternating convex and concave bends, multi-step returns and narrow-neck bulbs.
Other combinations fuse shared spines, reopen returns, withdraw dividers or
cut windows. Some sources receive a second coordinated direction edit or a
hub relocation so that the result changes more than one small edge detail.

The first preparation rung repeats each old reach four times in the chosen
fine authoring basis. This alone does not count as a new pattern. The comparison
basis is the actual prepared rung immediately before the shape edits, so
uniform rescaling cannot inflate the reported edit amount.

These are authored local transformation families applied by a program, not
autonomous invention or a learned aesthetic model. The native structure is
the executable result; captions and operation names do not choose its behavior.

## Two useful failures

Preserving the endpoints and closure of a fused path does not establish that
its new route avoids its other spans. Early lozenge examples satisfied those
local endpoint promises but retraced existing support. The producer now rejects
such fusion proposals before selecting another actual pair or an explicit cut.
The separate post-edit quality read remains necessary.
The [first failed fusion packet](../../experiments/QualitativeFrieze/results/lattice-transformations/history/failed-fusion.gojo.json.gz)
and its [recorded rule failure](../../experiments/QualitativeFrieze/results/lattice-transformations/history/failed-fusion.json)
are retained separately from the corrected catalogue.

Removing only one drawing history of a shared cell boundary may not create a
visible opening: an opposed neighbouring outline can still draw the same ink.
The window operation therefore withdraws corresponding ordered uses together.
Every cut still has its own actual path selection and native start witness.
This is why deleting a path occurrence and deleting visible field support are
different questions.

Some transformed diamond compartments also exposed endpoint-on-span contacts
and partially overlapping boundaries. The repair is not a renderer deduplication
or an observer creating topology. The supplier explicitly chooses a contact
agreement: actual published landmark prefixes, with optional actual neighbour
period offsets, propose interior cuts in an actual chord. A native refinement
checks their endpoint sum. A separate publication exposes the new vertices;
ordinary seam equality reads then accept or block their joins.

This scoped common-reach construction does not make every drawn intersection
a contact. A proper crossing without an offered endpoint remains unjoined.
Nor does it establish general intersection solving, fractional metric geometry
or a universal whole-span material law.

## Measuring change without confusing it with beauty

`LatticeGeometryChangeRead` connects two actual unit programs through one
declared common-reach basis. It retains affected old and new chord occurrences,
overlap correspondences and changed authored bends. An affected chord can
contain both changed and retained support; the exact loss and gain below are
calculated from its primitive support atoms. Its calculated support
ratio is the symmetric difference divided by the union of unique primitive
formal supports, weighted by `|dx| + |dy|` in that selected basis.

Straight subdivision, new wrappers, reversed path traversal and regrouping
four independent lines as one box can all have zero support change. The tests
protect those non-novelty cases. A real detour, gap or retargeted run has changed
support even though it may retain a grid or honeycomb ancestor.

The ratio concerns the **unit**, not the expanded field union. Neighbour
copies can retain support withdrawn from one occurrence. The runner therefore
also compares the normalized finite-field support/junction fingerprint against
the actual baseline field and presents their whole-pattern pictures together.
Neither check alone proves a satisfying visual change. A small alteration at
a dominant junction can matter more than a larger amount of edge decoration.

All final cases must pass native execution and the selected non-retracing
rules, have actual unit support change, differ in their finite field reads,
and remain distinct from the other final candidates. The diagnostics disclose
crossings, components, overlap, contact questions and finite boundaries. A
disconnected cut pattern is presented as separate strands, not a proof of a
connected tiling.

The gallery keeps the one-to-five ratings and notes from the baseline interface,
with a separate storage key. They can be exported and imported with source
fingerprints. They are the appropriate next evidence for a preference model;
the support ratio and complexity counts are not substituted for human taste.

## Execution and scope

```powershell
dotnet run --project experiments/QualitativeFrieze -c Release -- --lattice-transformations
dotnet run --project experiments/QualitativeFrieze -c Release -- --lattice-transformations --samples 2 --output artifacts/lattice-transformations-small
dotnet test Tests/QualitativeExecution.Tests/QualitativeExecution.Tests.csproj -c Release --filter "FullyQualifiedName~LatticeGeometry|FullyQualifiedName~LatticeTransformation"
dotnet test Gojo.slnx -c Release
```

The native packet includes every displayed stage and the geometric-change
witness. The runner imports the current ladder through the same exact reader
as the previous studies, checks actual ancestor identities, then executes the
finite field. There are no numeric carriers in the source constructions.
Common-reach counts and optional display coordinates are derived reads, rather
than measured values silently supplied to the executor.

`diagnostics.json`, `verification.json`, the browser report and the retained
native packets state the final executed scope. Automatic downstream rebasing,
unbounded geometric search, occupied-face tiling proofs and autonomous aesthetic
learning remain future work.

The recorded run admits all 100 candidates in a three-by-three field, with
100 actual unit-support changes and 100 distinct final finite-field reads.
It preserves 977 displayed stages and answers 877 actual ancestor queries after
native import. No source packet contains a numeric carrier. The selected checks
find no zero chords, retraced spans, blocked or missing seam obligations, or
overlapping supports.

Sixty-five fields are connected and 35 retain separate strands. There are 288
unjoined proper-crossing observations across the finite fields. The hub-moved
lozenge cases T055, T056 and T059 also retain 72 endpoint-on-span contact
observations without join agreements. These are visible attention cues rather
than failed promised joins; these cases do not establish that every geometric
touch is a material connection. Eleven cases actually fuse a shared spine;
nine other fusion-intent cases instead take the explicit cut fallback. The
outcome captions distinguish them.

The full solution passes 4,351 tests across 12 assemblies, including 26 new
structural cases for surgery, contact publication, support comparison and the
hundred-case generator. Browser verification passes 4,383 checks, walking all
977 displayed stages and checking ratings, imports, native packet digests and
desktop/mobile layouts. Acceptance is still separate from the gallery's human
ratings of visual interest.
