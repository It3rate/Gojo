# Reusable rule packs and revisable generation

The [interactive study](../../experiments/QualitativeFrieze/results/rule-pack-transfer/gallery.html)
applies the same native rule packs to ornament units, glyph constructions and
simple path networks, then follows parameter assumptions through generation and
revision. The [overview](../../experiments/QualitativeFrieze/results/rule-pack-transfer/overview.html)
shows the 54 constructions and the three generation stories.

The implemented advance is a reusable pack/application boundary and a bounded
connection between witnessed defaults, provisional parameter sharing and actual
execution. The contexts, symbolic templates and sample palette remain authored.
This is not learned default discovery or general program synthesis.

## What is reusable

`StructuralRulePack` contains an unbound target role, an actual default policy
and its exposed question services. Its native encoding is:

```text
pack = target role -> (policy ->
       (Closed(observation queries) ->
        (Closed(word-basis questions) ->
         (Closed(arrangement questions) -> Closed(participation questions)))))

application = pack -> (target-role binding ->
              (geometry passage ->
               (producer receipts -> (observed evidence -> policy receipt))))
```

The same predicate identity connects the policy to the producer service. Names
and domain labels are presentation only. The exact native reader rejects an
unadvertised rule predicate, duplicate or ambiguous services, and malformed
ordered scope. A source-free pack can be transported and bound to a fresh
target without the reference drawing or a side registry.

The four service families reuse existing readers: visible and mechanical
observation questions, optional finer word-basis geometry, complete route
arrangements, and finite participation bijections. The main experiment uses
the latter three. Focused tests also exercise the observation-query lane.

An application explicitly binds the target role to a public observation and
mechanical group surface. A finer geometry publication must describe that
actual observation and group inventory. A lookalike from another execution is
not acceptable evidence. Missing or mismatched geometry leaves those reads
Open, with the missing or blocked connection witnessed. It does not consult
private words or substitute a favorable answer.

The arrangement reader normalizes its independent frame when importing a
question. The pack retains the exact advertised predicate and an explicit
correspondence to that compiled question, preserving policy and exception
aliases. Whole-public-world transport tests cover the pack, target geometry,
policy and exact-rule exception together.

These components remain in the experimental `QualitativeFrieze` project. Their
reuse is demonstrated across the common published line/path contracts; no
cross-domain understanding is obtained merely by changing a name.

## Three packs, three domains, five contexts

Every pack inspects every one of the 54 independently executed drawings. The
domain and family columns never select a verdict. Each domain contains six
closed-course examples, six clamped-bridge examples and six independent-course
examples, including changed silhouettes, subdivisions, construction recipes,
deliberate apertures, unjoined contacts, extra branches and crossing variants.

| Pack | Required whole arrangement | Ordinary ornament matches | Glyph matches | Path-network matches |
| --- | --- | ---: | ---: | ---: |
| Closed course | One complete returning route | 4 | 3 | 3 |
| Clamped bridge | A route between two branching sites, with four free ends | 3 | 3 | 3 |
| Independent courses | Two complete independent open routes | 4 | 4 | 4 |

Each domain contributes eighteen drawings to each column's comparison, rather
than only the six examples named for that pack. The ordinary policy also has
strong defaults for explained encounters and resolvable closed construction
contours, a weak aspect preference, and unselected mirror and construction
inventory questions. Native geometry uses the explicitly supplied common-reach
word interpretation; no scene envelope is imposed in this study.

Five contexts exercise the same predicate graphs:

1. Ordinary realization.
2. Waive the exact encounter default while retaining its original evidence.
3. Also require the reference drawing-group inventory.
4. Prefer selected-frame mirror occupancy.
5. Offer the topology/group port without its optional geometry publication.

This gives **810 native pack applications**. **162 independently restored
pack-only comparisons** preserve the ordinary answers, preference ranges and
individual producer replies. Every drawing's native recipe is also independently
regenerated and checked by the strict graph reader.

Some useful distinctions are concrete:

- Requiring the original construction grouping reduces closed-course admission
  from ten drawings to eight. A single turning path and separately joined sides
  can have the same route concept while answering the construction question
  differently. The bridge and independent-course inventories happen not to
  further separate their admitted examples in this finite corpus.
- Four independent-course examples conflict with the encounter default. The
  exact waiver removes that preference departure without asserting a join or
  over/under order. This is a broad encounter exception: it also permits a
  coincident interval under that rule. A context that permits crossings while
  forbidding retracing should separately select the already available narrower
  collinear-overlap question.
- Mirror preference changes default burden while preserving structural
  admission. The same predicate is unused in the ordinary context.
- With geometry unavailable, hard topology admission stays unchanged. Each
  admitted drawing has two unresolved strong defaults, rather than two proven
  agreements. Overall policy Yes concerns the selected required claims; it does
  not certify the unresolved defaults.

This demonstrates reuse of connected structural questions across different
constructions. It does not demonstrate OCR, a universal aesthetics classifier,
or physical flow laws for the path networks. Those networks are topological
examples without simulated conserved traffic, capacities or hydraulic behavior.

## Defaults guiding generation

`RevisablePatternTemplate` retains a symbolic `UnitArrangementProgram`, exposed
parameter roles, public-port connection declarations and crossing selectors.
A move whose extent is an actual parameter role is expanded through a selected
role/parameter/value binding:

```text
H -> p                 H -> pH
V -> p                 V -> pV
p -> Closed(u)         pH -> Closed(u, u)
                       pV -> Closed(u)
```

The left construction proposes shared participation. The right construction
keeps the roles independently bound. Repeated positive atoms are uncalibrated
participation, not measured lengths. Equal samples in two independent parameters
do not make them the same parameter or assert a reusable equality.

Expansion preserves native path, word, port and crossing correspondences. The
existing native recipe runner then executes a new local drawing world. The
output role supplier follows actual ports and mechanical receipts to emitted
segments, reads their endpoint-word difference, and compares all supported
single-role occurrences. It does not echo the intended parameter values.
Missing bindings stay Open. Provably incompatible closure is Blocked; unresolved
participation stays Open. Compound-only roles and structured reach atoms are
outside the current complete role-read promise.

`RevisableRuleGeneration` uses the same proposal prior for three different
symbolic constructions: an ornamental compartment, a glyph H and a three-route
network. Each has two exposed roles and twelve proposals: three shared-parameter
samples and nine independently bound samples from a three-word palette.

The prior asks an exact finite participation question about the proposal's
parameter inventory. Its positive default prefers one shared parameter. The
negative context avoids exactly one parameter; for these complete two-role
proposals that selects two independent parameters. It is not a general law of
pairwise independence for an arbitrary number of roles.

Selection separates three reads:

1. Actual source publications and supplied capabilities determine which
   hypotheses remain admissible through `ProvisionalEquivalence`.
2. The default policy compares those proposals' binding structures. An explicit
   native sampling preference chooses a representative among undominated ones.
   Without that preference, alternatives remain available and no choice is made.
3. Only the selected hypothesis is executed. Its actual role values are assessed
   as a fresh **output** publication. Merely eligible or Open output conformance
   is insufficient to claim successful execution/conformance.

The receiver is given the authored symbolic template with open role values.
A source-free coarse route contract, derived from an independently executed
supplier, is checked after generation. That contract is a held-out critic here;
it does not infer, select or reconstruct the template. No automatic retry or
repair occurs if the selected proposal cannot execute.
"Held-out" means outside the selection process: supplier and receiver still use
the same authored template, so this is not a statistical test on unseen templates.

## Eight stages of belief revision

All three stories reveal one fixed source event. The actual source role values
come from its executed output; the receiving engine initially sees neither.
The native event timeline preserves earlier stages and explicit changes of
publication scope.

| Stage | Source equality read | Chosen realization | Consequence |
| --- | --- | --- | --- |
| No role values | Open | Shared sample 1/1 | Equality is assumed, not observed |
| Horizontal role revealed | Open | Shared sample 2/2 | The sample changes; the equality assumption remains provisional |
| Both roles revealed | No | Independent sample 2/1 | One shared-role assumption is withdrawn; coarse topology survives |
| Two conflicting accounts | Open | None | No silent supplier choice; previous output is historical |
| Explicit working account | No | Independent sample 2/1 | The other account remains retained outside the working scope |
| Independent prior, fine values withheld | Open | Independent sample 1/1 | Same appearance as the first sample, different parameter structure |
| Sharing deliberately unused | Open | Independent sample 3/1 | Twelve alternatives remain undominated; explicit sampling order chooses another |
| Only shared proposals offered | No | None | The offered proposal bank cannot satisfy unequal roles |

There are **24 stages**, **18 newly committed receiver outputs**, and six
stages with no new output. Every committed output satisfies independently read
role conformance and the held-out coarse route contract. The six no-output
stages retain a previous drawing for inspection without treating it as a current
answer. Supplier executions are additional, separate worlds.

The limited-bank control restricts offered hypotheses; it does not prove that
the template interpreter is incapable of independent parameters. Explicit
account scope is also not learned reliability. Old publications are not
automatically expired or replaced by a latest-revision rule. A changing physical
source would require an explicit revision/time scope rather than asserting all
historical values simultaneously about one event.

## What transfers, and what remains supplied

Implemented reusable parts include the pack's native service inventory and
target binding, authority scopes and exceptions, source-free route and count
questions, symbolic parameter expansion, actual role-value publication, proposal
sharing prior, candidate-preserving choice, and witnessed revision history.
The pack, template and prior all have standalone native readers. Tests restore
a complete prior/template/source/proposal world and make domain and choice
correspondence explicit before repeating the revised output.

Supplied parts include which contract matters, the symbolic construction,
role interpretation, positive participation basis, default authority, sample
palette, account scope and representative preference. No calibrated probability,
automatic context recognition, default inheritance, learned strength or
autonomous program invention is established. The current policy witnesses are
execution audits with finer evidence retained, not minimal communication packets.

The next useful test is selection among several independently supplied symbolic
templates using held-out questions, then revision that splits or changes a
template rather than only its parameter partition. Counterexamples should remain
connected so a default is strengthened only when it improves new queries without
silently excluding valid alternative realizations.

## Reproduce and inspect

```powershell
dotnet run --project experiments/QualitativeFrieze -c Release -- --rule-pack-transfer
node experiments/QualitativeFrieze/tools/check-rule-pack-transfer.cjs
dotnet test Gojo.slnx
```

The checker supports `--data-only`; browser checks use the same local
Playwright/Edge setup as the earlier studies, overridable through
`GOJO_PLAYWRIGHT_MODULE` and `GOJO_BROWSER`. It checks saved decisions, source/
assumption/output separation, all image references and narrow-screen layouts.

Source files are `StructuralRulePack.cs`, `RevisablePatternTemplate.cs`,
`RevisableRuleGeneration.cs`, `RuleTransferCases.cs` and
`RulePackTransferExperiment.cs`. `transfer.gojo.json.gz` retains all ordinary
applications, representative context applications, templates, priors, supplier
links and full generation timelines. All matrix rows can be regenerated; the
archive avoids duplicating every intervention proof. No kernel rules changed.

Verification passed 34 focused native tests for the new components and 4,756
tests across all twelve solution test projects, with no failures or skips.
Browser/data checks passed 138 selected browser states, all 150 SVGs and 194
local references, including cross-context invariants and explicit separation of
source equality, proposal sharing and output conformance. Desktop and mobile
views were inspected. The runner builds without warnings or errors.
