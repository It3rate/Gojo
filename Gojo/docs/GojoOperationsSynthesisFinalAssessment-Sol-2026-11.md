## Merge blockers in the optional backend

### A same-tick port write can send the compiled follower to the wrong site

Build a two-site store and a toggle wiring whose only row initially refers to site 0. Publish the reference bit from that wiring's `Rows` store. Put a conserving one-unit transfer through that port immediately before the toggle. Both engines end with the row referring to site 1. On both `Step()` and `Settle(1)`, the interpreter toggles site 1 and the compiled path toggles site 0. The compiled report says it used a fast path and the saved bytes differ.

The self-rewiring check looks at `Surface.Home`. A port reaches the row store through a lane and has no direct home in that check. The plan still qualifies at the start of the tick and the earlier fallback wiring can change the reference before the later compiled wiring uses it. Treat writes through a port or socket that can reach scheduling state as a reason to run the containing schedule canonically until their effects can be qualified. [Self-rewiring check](../../Gojo.EncodingC/Compilation/CompiledPlan.cs#L529) · [Ordered compiled step](../../Gojo.EncodingC/Compilation/CompiledPlan.cs#L317) · [Surface ownership contract](../../Gojo.EncodingC/Substrate/Surface.cs#L43)

### Recruiting a position can leave a delivery stranded at an apparent quiet step

Put an earlier wiring that recruits spare destination position 1 through `Store.Life` before an identity-mapped two-row `Flows.Convert(1,1,1,1)`. The interpreter immediately moves the available packet into position 1 when that position becomes live. The compiled packet path still excludes it. In a fresh run, compiled `Settle(4)` reports quiet after two ticks with the packet undelivered.

The compiled mask captures the original runnable lanes. The runtime check verifies that those lanes are still live. A lane recruited earlier in the same tick stays outside the mask. The topology fallback should cover recruitment and retirement of positions that later wirings use, alongside edits to wiring rows. [Compiled runnable mask](../../Gojo.EncodingC/Compilation/CompiledPlan.cs#L855) · [Live coverage check](../../Gojo.EncodingC/Compilation/CompiledPlan.cs#L1180)

## Numeric and recognition contracts

- **Keep the scopes and uncertainty attached.** Two disjoint eligible pools can produce `5/10`, two portions on one whole can produce `5/5`, and explicit common refinement can give `11/15` for `2/5 + 1/3`. A point budget and the number of judgments are separate. An exact ratio supplies no confidence interval. Save/load covers pending `{5,6,7}/10` and a rounded value tied to the correct residue. The native fractional-bound fix correctly encloses the interval in either target direction. [Scope tests](../../Gojo.EncodingC/Tests/SynthesisScopeTests.cs) · [Unit tests](../../Gojo.EncodingC/Tests/SynthesisUnitTests.cs) · [Publication and residue tests](../../Gojo.EncodingC/Tests/SynthesisPublicationTests.cs) · [Native bound fix](../Structures/QualifiedReadSurface.cs#L243)
- **State the limit of live-denominator pooling.** `Portions.WirePool` validates the input portions and sums their two roles. It needs scope and basis evidence from the caller. Binding the same `2/3` twice yields `4/6`. When each input numerator and denominator is in `{2,3}` and the pooled numerator is constrained to 5, local settlement retains denominator support `{4,5,6}`. A joint query choosing 4 contradicts, and the exact possible denominators are 5 and 6. Describe these separate supports as conservative. For `Project`, name the remainder's basis explicitly. A stored integer `r` is `r/d₂` source ticks or `r/(d₁d₂)` of the whole. [Portion laws](../../Gojo.EncodingC/Laws/Portions.cs#L77)
- **Exact restoration passed the bounded checks.** Two hidden roles recover min, max, and absolute difference. Restoration requires full table equality and reuses the original accounting. Two search edges need narrower documentation or follow-up tests. `Residues` cannot take the blocked-bit premise that `Compare` and `Restore` accept, so it misses a marked form of the same minimum that it finds unmarked. A `maxCapacity: 64` search can throw while constructing a unary role, whose capacity stops at 63. These are discovery coverage gaps, not evidence of an unsound restoration. [Residue search](../../Gojo.EncodingC/Laws/Recognition.cs#L289) · [Exact compare and restore](../../Gojo.EncodingC/Laws/Recognition.cs#L500)
- **Guard the domain before claiming it was checked.** Four roles of size 65,536 make a domain of `2^64`. The unchecked product wraps to zero in `Relations`, which returns `Checked = true` with no unexplained tuples after enumerating none. With those four inputs and a bit target, `Probe` likewise returns no question for candidates `target = input₀` and `target = 0`, even though input₀ = 1 distinguishes them. Bound the product before multiplying and assert the declared out-of-budget behavior. I would fix this before integration because `Checked` is part of the evidence a caller uses. [Relation qualification](../../Gojo.EncodingC/Laws/Recognition.cs#L129) · [Probe domain check](../../Gojo.EncodingC/Laws/Recognition.cs#L480)

## Performance and verification

Neon's results cover setup and execution on prepared graphs, with layout and fallback measured separately. In an independent Windows Release spot check, I used 4,096 lanes of three binary-coded decimal rungs. The two inputs at lane `i` were `(73i + 17) mod 1000` and `(31i + 7) mod 1000`. Over seven trials after two warm-up pairs, median `Engine.Settle(8)` was **298.072 ms**, and median `Compile + Settle(8)` was **0.478 ms**. The compiled path ran and matched ticks and saved bytes on every pair. Both timings start from prepared graphs. Eligibility, layout and fallback mix can change the end-to-end cost.
