[normal] Order of operations is a first class primitive in math that defines the sequence of operations, but parallel operations are mostly not specifiable. This is because we fixate on results rather than processes for equations. And it's one of the reasons calculus can seem so confusing.
[normal] This is easiest to see in 2D (parallel vs sequential matters). The operations down 1 and across 1 give an 'L' when done sequentially, and a '\' when done in parallel. Translating this to 1D (1+1) we can get two segments joined (sequential) or a single segment of length 2 (parallel) where every bit of each segment is piecemeal merged into a new one.
[normal] A better mental model of this is adding four rows of numbers together using column arithmetic (parallel), or adding up receipts on a calculator one after another (sequential).
[normal] The same is true for multiplication. 3x3x3 stretches a value to 3, stops, stretches that to 9, stops, and then stretches that to 27. If you imagine each of these steps taking the same amount of time, there are three distinct speeds. This is sequential.
[normal] An example of the parallel version of multiplication is powers. 3^3 starts with three values stacked in a column. As the first stretches to 3, the second tracks it to remain three times longer, and the third tracks the second, remaining 3x longer than it. There are also three speeds here, but they all happen at the same time on different values. We 'care' about the last value, which is a segment of 27 that was formed at a constant speed.
[normal] If you animate these, you'll find a lot of ambiguity, and a lot of things missing. Right off the bat, we distinguish between parallel/sequential versions of addition. We do with multiplication, but only with the same number (there is a parallel 3x3x3, but not for 3x4x7). Polynomials seem to be a parallel/sequential combination, where we sequentially step between each in increase in power. Even with 2D, where it is absolutely required, there is nothing in math that distinguishes an 'L' from a '\', that is just in the code or metadata somewhere.
[normal] This matters a lot when trying to encode motions. And encoding motions matters a lot when trying to encode concepts because so many thoughts we have are metaphorical 'change motions'. You can just make decisions and write code, but these are fundamental facts about combining values at the  level of other operations on numbers. Rules here can't be arbitrary or inconsistent, they need to be at the system level.
